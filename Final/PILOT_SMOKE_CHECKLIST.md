# Aurora Launch — контрольный сценарий первого сеанса

**Аудитория:** Антон + пилот (Materia Medica) при первом совместном запуске.
**Цель документа:** ровно проверить, что v0.1.0 GA работает в нормальном потоке, прежде чем оставить продукт в руках клиента на самостоятельную работу.
**Длительность:** 25–35 минут на первый прогон вживую.

> Если хотя бы один пункт даёт сбой — отметить как «🔴 заметка», продолжить дальше (если возможно), вернуться к проблеме после прогона. Не править в живую при клиенте — записать и поправить дома.

---

## 0. Предусловие (за 1 день до встречи)

- [ ] Свежая установка Aurora Launch v0.1.0 на ноутбуке, на котором будет проходить встреча.
- [ ] Файл `sample.aurora` лежит в `<AppData>/aurora-launch/samples/kagotsel_venarus.aurora` или передаётся вручную.
- [ ] Логи приложения чисты (или удалены), чтобы первый прогон сгенерировал свежий след.
- [ ] Резервная копия пустого `projects.db` сохранена — на случай если в ходе встречи всё пойдёт не так и надо начать с нуля.
- [ ] Проверено: ссылка `https://verify.auroraai.pro/<bundle-hash>` отвечает (можно открыть позже из приложения).

---

## 1. Знакомство с продуктом (5 мин)

1. Запуск приложения с ярлыка.
   - **Ожидание:** появляется приветственная анимация Aurora 800 мс.
   - **Проверка:** через приблизительно 1 секунду переход на экран выбора категории бренда.
2. Выбор категории «Фарма OTC».
   - **Ожидание:** клик визуально подтверждается (рамка карточки выделяется), затем переход на обучающую карусель.
   - **Проверка:** в `localStorage` появилось `aurora.category = pharma_otc` (открыть DevTools только если что-то пошло не так).
3. Обучение в 5 слайдов.
   - **Ожидание:** стрелки → / ← переключают слайды, кнопка «Пропустить» доступна с первого слайда.
   - **Проверка:** на пятом слайде появляются две кнопки — «Открыть пример» и «Начать с нуля».
4. Нажать «Открыть пример».
   - **Ожидание:** загрузка примера `kagotsel_venarus` за 3–5 секунд, переход на историю проекта.

---

## 2. Первый прогноз (10 мин)

5. Открыть мастер прогноза (кнопка «Новый запуск» с главной либо из истории).
6. **Шаг 0 «Импорт».** Проверить, что наверху виден баннер `Похоже на ваш предыдущий запуск` (M-06 pattern learning), если в системе уже есть прошлый проект.
   - **Заметка:** при первом запуске у пилота прошлых проектов нет — баннер не должен показаться. Это правильное поведение.
7. Выбрать тот же файл-образец или собственный `.xlsx` Materia Medica.
8. **Шаг 1 «Сопоставление».** Подтвердить колонки бренд / период / продажи. Кнопка «Применить» — переход дальше.
9. **Шаг 2 «Прокси».** Выбрать бренд-прокси из выпадающего списка.
10. **Шаг 3 «Похожесть».**
    - **Ожидание:** показывается радар-диаграмма, similarity_score выводится числом.
    - **Проверка:** при низкой похожести (< 0.5) viewer показывает предупреждение «нужно больше данных».
11. **Шаг 4 «Якоря».** Установить значения. Кнопка «Set anchors» переключает в «Anchors set ✓».
12. **Шаг 5 «Прогноз».** Кнопка «Start forecast».
    - **Ожидание:** прогресс-бар реально движется (это не таймер-театр), события `forecast/progress` идут из Python sidecar.
    - **Ожидание:** конус прогноза рисуется точка за точкой.
    - **Время:** 5–25 секунд в зависимости от длины горизонта.
13. **Шаг 6 «Сертификат».** Открыть Methodology Certificate.
    - **Проверка:** видна Ed25519 подпись, методологический хеш, метка `aurora_launch v0.1.0`.

---

## 3. Магические возможности (10 мин)

14. **Объяснение прогноза (M-03).** На странице Inspector найти секцию «Объяснение». Прочитать вслух 3-абзацный нарратив CFO-формата.
    - **Ожидание:** локально сгенерированный текст; упоминает What / Why / Risks.
    - **Заметка:** язык русский. Если cloud-апгрейд через Claude API ещё не подключён — пилоту сказать «это локальный шаблон, через 2 недели включим живую модель».
15. **Воспроизведение в Python (M-09).** Нажать кнопку «🐍 Воспроизвести в Python» в Inspector.
    - **Ожидание:** появляется модальное окно с сгенерированным Python-скриптом.
    - **Проверка:** кнопка «Копировать» работает, кнопка «Скачать» сохраняет `.py` файл.
    - **Демонстрация ценности:** показать, что код можно открыть в любой среде Python и получить тот же прогноз.
16. **История версий с семантическим diff (M-05 + Smart diff).**
    - Сохранить версию прогноза.
    - Изменить один anchor, перепрогнать прогноз, сохранить вторую версию.
    - Открыть страницу истории проекта.
    - Выбрать обе версии чекбоксами.
    - **Ожидание:** появляется панель «📊 Что изменилось» с разницей точки прогноза, ширины CI, режима движка.
    - **При наведении мыши на строку при `selection=1` (M-05):** diff подгружается заранее — клик «Сравнить» открывает мгновенно.
17. **Анимация уверенности (M-10).** Если CI второй версии уже первой — появляется надпись «Прогноз становится надёжнее» с пульсацией.
18. **ModeBadge.** В Inspector видна метка движка (Pure Transfer / Bias Check / OLS+priors / Bayesian+priors). Если режим понизился из-за нехватки данных — badge подсвечивается жёлтым с подсказкой «упрощённый».

## 4. Подсказки и поддержка (5 мин)

19. **Daily insight баннер (M-07).** Закрыть приложение, открыть снова через 30 секунд.
    - **Ожидание:** на главной появляется баннер (если есть актуальный insight).
    - **При первом открытии:** insight = «Готовы создать первый прогноз?» если onboarded и 0 проектов.
20. **Палитра команд (Cmd+K / Ctrl+K).** Нажать клавиатурное сочетание.
    - **Ожидание:** открывается окно палитры, поиск по командам работает, Escape закрывает.
21. **Smart defaults (M-04).** При создании нового проекта (поверх существующего) проверить, что часовой пояс и валюта подобраны автоматически из системных настроек.
22. **Отправка диагностики.** Меню «Помощь» → «Отправить диагностику».
    - **Ожидание:** появляется ZIP с логами + state snapshot.
    - **Проверка:** SHA-256 + текстовые поля редактированы (имя клиента, IP, токены — все вырезаны).

---

## 5. Стрессовые проверки (5 мин)

23. **Резервная копия.** Закрыть приложение. Сделать копию `projects.db` куда-нибудь в OneDrive/Yandex.Disk. Снова открыть приложение — список проектов сохранён.
24. **Многооконность.** Открыть Aurora второй раз (двойной клик на ярлык).
    - **Ожидание:** второе окно показывает понятное сообщение «Aurora уже запущена» вместо тихого падения.
25. **Внезапное закрытие.** Закрыть приложение через диспетчер задач (имитация краха) сразу после старта прогноза.
    - **Ожидание:** при следующем старте — банер «Возобновить незавершённый сеанс» или восстановление данных без потерь.

---

## 6. Что фиксировать (заметки для аудита)

После сеанса записать в `Final/PILOT_SESSION_LOG_<дата>.md`:

| Категория | Что было | Что записать |
|---|---|---|
| 🟢 Хорошо | Шаги прошли как ожидалось | Кратко: «1–12 без проблем» |
| 🟡 Заметка | Работало, но криво/медленно/неочевидно | Пункт + время + что именно неочевидно |
| 🔴 Ошибка | Сбой / падение / неверный результат | Скриншот + лог + точные шаги воспроизведения |
| 💡 Пожелание | Клиент попросил/предложил | Цитата + контекст |

После — добавить в Linear/Kanban: 🔴 → BUG срочно; 🟡 → backlog следующего тага; 💡 → product backlog.

## 7. Контакт после сеанса

- В тот же день: отправить клиенту thank-you email с сводкой того, что показали.
- В течение 48 часов: разослать 🔴 и 🟡 в `aurora-meta/SESSIONS/`.
- Через неделю: follow-up — «как идёт, что хочется доделать».
