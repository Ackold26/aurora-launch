# Proxy Intake Protocol

**Status:** Authoritative for Aurora Launch (Phase B)
**Restores:** D002 SESSION_001 2026-05-04 (отказ от donor library) as primary architectural decision
**Supersedes:** `04_Sprints/DONOR_LIBRARY_SHORTLIST.md` (deleted 2026-05-06)

## TL;DR

Aurora Launch не использует предзаготовленную библиотеку «доноров». Каждый прогноз начинается с того, что **клиент сам называет proxy-бренд** под свой конкретный кейс. Aurora принимает proxy ad-hoc, собирает данные продаж и рекламы из DSM Group / Mediascope, обучает модель под именно этого proxy, и применяет её к новому бренду клиента.

Никакая «библиотека учителей» не строится заранее.

## Почему так

Решение D002 (Антон, 2026-05-04) и подтверждение 2026-05-06:

1. **Библиотека не покрывает индивидуальные ситуации.** Клиент с новым бренд кофе требует proxy-бренд кофе (например, конкретный конкурент в той же ценовой категории и регионе). Заранее заготовленный пул из 5 фарма-брендов ему бесполезен.

2. **Aurora работает не только в фарме.** Эконометрика уже сместилась в сторону агентств и FMCG-ритейла. Будущие клиенты Aurora Launch — из косметики, продуктов питания, бытовой химии, телекома, банкинга, образования, e-commerce. Фарма-доноры покрывают долю рынка <5%.

3. **Не во всех категориях есть подходящий proxy в pre-built.** Совсем новые ниши (новые БАД-форматы, новые цифровые сервисы, новые форматы стриминга) не имеют близких аналогов в нашей библиотеке — нужен живой подбор под конкретный кейс.

4. **Custom proxy от клиента всегда точнее.** Клиент знает свой рынок, своих конкурентов, своих ближайших аналогов лучше нас. Наш job — построить математику переноса от любого названного proxy к новому бренду.

## Workflow приёма proxy

### Шаг 1 — Discovery call (Sales)

Sales team или Аврора-консультант обсуждает с клиентом:
- Категория и подкатегория нового бренда
- Целевая аудитория, ценовой сегмент, региональное покрытие
- Ожидаемый медиа-микс
- **Какой существующий бренд клиент считает наиболее похожим** — это будущий proxy

Клиент часто сам предлагает 1-3 кандидата. Если затрудняется — Аврора-консультант помогает сузить выбор по 6 параметрам подобия (категория / цена / размер / дистрибуция / медиа-зрелость / стадия зрелости).

### Шаг 2 — Verification of proxy availability

Аврора проверяет доступность данных для предложенного proxy:
- Есть ли бренд в DSM Group weekly?
- Есть ли его рекламные расходы в Mediascope AdEx и TV Index?
- Достаточно ли исторических данных (минимум 104 недель)?

Если данные недоступны — возврат к шагу 1 для альтернативного proxy.

### Шаг 3 — Anonymization agreement

Клиент подписывает соглашение об использовании proxy в обезличенном виде:
- Название бренда заменяется кодом (например, COFFEE-2026-Q2)
- Цифры продаж и расходов умножаются на синхронизированный случайный коэффициент R (важно: единый для всех метрик, чтобы сохранить ROI ratios)
- Даты сдвигаются на ±N месяцев
- Категориальные признаки (АТС, ценовой сегмент) сохраняются для подобия

Aurora не получает идентифицирующую информацию о proxy на уровне платформы. Только sales-консультант знает связь "код ↔ реальный бренд", и эта связь не сохраняется в bundle-артефактах.

### Шаг 4 — Data ingestion

Aurora Data Studio (компонент C2) собирает:
- Недельные продажи proxy из DSM Group (адаптер dsm)
- Рекламные расходы proxy из Mediascope AdEx (адаптер mediascope_adex)
- Рейтинги/охват из Mediascope TV Index (адаптер mediascope_tv_index)
- Опционально: данные из DigitalBudget или клиентских таблиц

Все три потока приходят в каноническую форму через `aurora_studio.adapters.base.CanonicalRecord`.

### Шаг 5 — Trust 3 model training

Запускается обучение байесовской иерархической модели на данных proxy:
- Длительность: 2-3 часа в зависимости от частоты данных и количества каналов
- Выход: pickle-артефакт с posterior samples + диагностикой сходимости

Модель **не сохраняется как переиспользуемый «учитель»**. Она существует только для обслуживания конкретного клиентского кейса.

### Шаг 6 — Transfer to recipient brand

Применение математики переноса (Adaptation Layer):
- Извлечение adstock decay + Hill saturation из proxy posterior
- Калибровка β по anchor-данным от клиента (рыночный размер, эластичность, planned share)
- Генерация прогноза с конформными интервалами на 12/26/52 недели

### Шаг 7 — Methodology Certificate

Bundle подписывается через C7 Web Verifier (Ed25519 + Yandex.Cloud KMS), даёт клиенту аудитируемый сертификат с:
- Хешем proxy-данных (обезличенных)
- Хешем модели
- Параметрами трансфера
- Конформной оценкой неопределённости

## Что это значит для архитектуры платформы

### Что не меняется (продолжает быть правильным)

- **C2 Data Studio адаптеры** работают независимо от того, есть библиотека или нет — они принимают данные **любого** proxy ad-hoc
- **Hierarchical priors / similarity scoring** — применяются к proxy от клиента в реальном времени
- **Anonymization protocol** — применяется к каждому proxy отдельно, не ограничен фарма-кейсами
- **Math layer** (`aurora_inference`) — не зависит от категории, работает с FMCG/cosmetics/telecom/banking данными так же как с фарма-данными

### Что меняется

- **Sprint B0.5 BC corpus** — переосмысливается как «тест конвейера на сгенерированных данных плюс 1-2 реальных кейса когда они появятся», а не «валидация предзаготовленной библиотеки»
- **Sprint B6 pilot acceptance criteria** — теперь это «клиент называет proxy → Aurora строит прогноз за разумное время», а не «client outcomes match library benchmark»
- **Sales playbook** включает раздел по подбору proxy в discovery call
- **Pricing tiers** не зависят от библиотеки — каждый прогноз требует одинакового объёма работ независимо от proxy

## Позиционирование

**Aurora Launch — продукт прогноза продаж для любых новых брендов в любой отрасли.**

- Клиент называет proxy
- Aurora собирает данные
- Aurora строит модель
- Aurora даёт прогноз с прозрачной методологией и конформными интервалами

Не «фарма-инструмент». Не «инструмент с заготовленной базой». Это сервис **построения индивидуальных моделей под каждый клиентский запрос**.

## Что это решает в коммерческом плане

| Аспект | До (с библиотекой) | После (proxy intake) |
|---|---|---|
| Доступный рынок | Только категории, представленные в библиотеке (фарма) | **Любая категория** где есть DSM/Mediascope данные |
| Капитальные затраты | Лицензирование 5+ донорских брендов upfront | Покупка данных под конкретный заказ (per-deal cost) |
| Время до первого пилота | 4-6 недель на сбор данных + обучение библиотеки | Прямо к первому клиенту |
| Маркетинговое позиционирование | «Фарма-инструмент» | «Продукт прогноза для любых отраслей» |
